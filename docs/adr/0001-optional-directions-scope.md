# ADR 0001：可选优化方向的取舍

- 状态：已接受
- 日期：2026-10-09
- 范围：仓库审计（2026-10）中列出的可选优化方向

## 背景

仓库审计列出了 7 个可选优化方向。经过成本、风险与阻塞点评估，只有其中 3 个适合实施；
其余 4 个因平台限制、成本过高或收益不足而**保留不做**。本记录用于留痕，避免后续重复讨论。

原始编号在整份审计中保持不变：**本次实施 1、4、5；暂不实施 2、3、6、7。**

## 决策

### 已实施

**1. CDN 本地 vendor + 降级提示**

- 全部第三方库（MathJax、marked、highlight.js、Mermaid）已随仓库发布到 `assets/vendor/`，
  页面不再发出任何外部请求；来源、版本、字节数与 sha384 见 `assets/vendor/README.md`。
- 采用 `mathjax@3.2.2/es5/tex-svg.js` 而非 `tex-mml-chtml.js`：CHTML 需要运行时抓取 woff 字体
  目录，SVG 输出自带字形、无额外请求。
- 采用 `mermaid@10.9.8/dist/mermaid.min.js`（UMD 单文件）而非 ESM 入口：ESM 入口只有 76 字节，
  实现位于按需加载的兄弟分片，本地化需要引入分片图。
- `assets/roadmap.js` 在任一库缺失时插入 `.vendor-warning` 提示条，替代此前的静默失败。
- 代价：仓库体积增加约 5.6MB（`tex-svg` 2.1MB + `mermaid.min.js` 3.3MB + 其余约 0.16MB）。

**4. index.html 二级入口补全**

- `index.html` 新增「其他内容」区块，链接 `learning-paths/`、`cases/`、`interview/`、`prompts/`，
  此前除 `learning-paths/` 外均不可达。

**5. 跨页“最近学习”入口**

- 每个 roadmap 页把自己登记到 `localStorage['roadmap:recent']`（最多 12 条），`index.html`
  渲染其中前 6 条；路径以站点根为基准计算，因此换域名/换端口后仍然有效。

### 暂不实施

**2. 动画/案例产物走 LFS 或 release 附件** —— 阻塞：平台限制

- GitHub Pages **不支持 LFS**：勾取后的文件是 LFS 指针文本，Pages 会把它当内容返回，动画版与其
  `roadmap-animations/` sidecar 会直接失效。
- sidecar 通过相对路径 `iframe` 互相引用；改为 release 附件 URL 会同时破坏相对引用与本地/离线
  打开（`file://`）能力。
- 已完成的替代动作：删除本地产物（渲染页与视觉核验证据，约 12MB），保留功能必需的动画 sidecar。
- 如需进一步瘦身，唯一低风险路径是拆分动画资源清单后单独打包，收益有限，暂不做。

**3. i18n 双语** —— 阻塞：成本与内容所有权

- 更正一个常见误解：`learning-paths` 的 `ops-path-language` 是 **Go/Python 学习轨道选择器**，
  不是界面语言开关；仓库当前**没有**可复用的 i18n 机制。
- 界面层（`index.html`、`assets/roadmap.js`、learning-paths 文案）技术上可行（约 2–3 小时），
  但缺乏真实需求，暂不做。
- 内容层（118 篇笔记、约 27 万行中文）不做：需要持续的人工/模型翻译与校对，每次内容更新都要维护
  中英两份，且译文质量不可自动化验证。若将来要做，真正的阻塞是内容所有权与人工校对，而非技术。

**6. 动画版也抽共享资源** —— 收益不足

- 只有 2 个页面（`full-animated-roadmap.html`，933KB / 263KB），其内联 CSS/JS 与标准页**不同且
  不可复现**；动画时间线与交互的回归难以自动化验证，风险高于收益。

**7. cases 逐篇按模板全文重构** —— 成本过高

- 83 篇案例（每篇 30–60 分钟起，且需回原文核对事实）预计 40–80 小时；改写会丢失“保留原分享
  结构”的价值并可能引入事实偏差。
- 已采用的替代方案（来源/类型/状态元数据块 + 校验器）已覆盖署名与状态需求，见
  `cases/README.md` § 来源与状态。

## 影响

- 页面零外部依赖，离线与受限网络可直接打开；升级第三方库需要手工替换文件并重新验证（流程见
  `assets/vendor/README.md`）。
- 仓库体积增加约 5.6MB，与本轮删除的约 12MB 本地产物相抵后仍为净减。
- `scripts/build-roadmaps.sh` 默认只刷新数据载荷；需要整页模板时显式传 `--full-template`，
  否则会把页面退回内联模板并恢复 CDN 引用。

## 后续

- 第三方库升级：按 `assets/vendor/README.md` 的流程执行，并在每类页面上做一次浏览器验证。
- 若 GitHub 未来支持 Pages + LFS，可重新评估方向 2。
- 若出现真实的英文读者需求，先做界面层 i18n（方向 3a），内容层需要独立的翻译流水线与校对流程。
